# 科幻电影 Agent · MVP 产品基线

**更新日期：** 2026-09-06

**状态：** 核心产品与关键交互方向已确认；三栏、主题、Windows 本地个人部署和密钥配置已定，可点击原型已获授权、待开始。具体界面体验尚待原型审阅，电影能力未实现；技术接入与真实验证仍待完成。

**阅读关系：** 本文定义做什么；[交互决定记录](creative-interaction.md)记录具体交互；[技术评审基线](../architecture/technical-baseline.md)区分技术方向和候选。文档之间如有冲突，以所有者最新决定为准，修正文档后再实施。

## 1. 产品目标

让不熟悉 AIGC 的用户，通过自然语言和多轮对话，把想法拍成一部有故事、有连续声画、可以继续修改的 90–120 秒科幻短片。用户无需提供素材；人物、场景、图像、视频和声音可以逐步生成。

所有者以《星际穿越》《挽救计划》《流浪地球2》作为审美参照，关注画面质感、故事吸引力、连续性、声音和修改体验。这是创作方向，不代表模型已能达到相同制作水准，也不把这些影片的剧情和角色当作默认生成内容。

| 项目 | 当前已确认方向 |
|---|---|
| 首版成片 | 90–120 秒，有完整声画，明显生成问题得到处理；是否适合发布由用户判断 |
| 时间目标 | 约 30 分钟得到第一条完整可看片；尚未实测，不是到时自动停止的规则 |
| 成本目标 | 此前讨论的约 150–220 元/片只作参考预期，不作为用户必须遵守的硬上限；实际成本仍需计量 |
| 默认输出 | 16:9、1080p，保留生成源文件质量；输出分辨率不等于已获得电影质感 |
| 视频模型方向 | MiniMax H3 首选，Seedance 2.0 标准版备选 |
| 首轮重心 | 故事如何拍出来、跨镜连续、声音和修改体验 |
| 界面 | 对话为主，右侧承载可编辑剧本、图片、视频和必要的声音素材 |
| 部署与模型配置 | Windows 本地个人部署，通过电脑浏览器使用；用户自备模型 API Key，设置页引导填写并检查连接；macOS／Linux 后续适配 |

影片可以有多人、多场景、非线性叙事和对白，具体组织依剧本需要决定。对白与口型支持按剧情需要使用，不是重点强化的唯一场景。人物数、镜头数、场景数、反转和固定节拍顺序均不设统一模板；复杂任务的实现效果仍需真实验证。

## 2. 共创与托管

两种模式使用同一个项目、产物、版本和生成能力，区别在于用户授权的决策范围。

| 维度 | 共创（默认） | 托管（明确授权） |
|---|---|---|
| 创作决定 | Agent 理解、给出自己的意见和方案，用户确认后执行 | Agent 在授权范围内自主推进 |
| 审核 | 在已确定的关键节点展示产物并等待用户；模型可按需要提出额外讨论 | 已授权跳过的审核不重复打断；超出授权范围的改变仍需沟通 |
| 可见性 | 持续展示实际进展和已产出的内容 | 同样持续展示，不能长期黑箱 |
| 修改 | 按用户确认的修改方案执行 | 在当前授权范围内执行修改 |
| 切换 | 可随时在同一项目切换模式 | 保留意图、素材、版本和已有批准 |

支持部分托管，例如声音交给 Agent、视觉继续共创。入口通过自然语言表达，MVP 不要求用户先配置复杂权限面板。

已有审核结构与运行中的具体调度分开：模型可以判断创作影响和何时采取哪种操作；程序必须可靠保存批准范围、任务状态和对应版本。

## 3. 从一句话到首版影片

下面描述面向用户的创作过程，不是固定 Agent 数量或不可变的执行图。

### 3.1 意图理解与故事提案

用户可以只提供题材、感受、一个设定或一个画面。Agent 通过必要的对话理解意图，也可以补充人物、冲突、发展和结尾，明确哪些关键内容是自己的建议。

右侧故事提案有三个内容区：

1. 片名与一句话故事。
2. 完整故事，包含结尾；开放结局写明最后呈现什么、留下什么疑问。
3. 准备怎样拍，表达与故事相关的视觉、声音和节奏选择。

完整故事是主要内容，初始建议正文约 300–500 个中文字，随故事调整，不作字数门槛或时长换算规则。人物与关键设定默认融入正文，有理解困难再展开说明。左侧对话承载 Agent 的理解、推荐理由、实际顾虑和当前最值得讨论的问题。

### 3.2 正式剧本

提案获得认可后，按场景展开正式剧本。每场写清地点与时间、画面与动作、对白与关键声音。用户在右侧逐场阅读和手动修改；具体镜头拆分与生成提示词由后续制作规划展开。

保存手动编辑不自动生成或重生成媒体。只有用户明确要求应用修改，才进入修改理解和执行流程。Agent 不能用旧稿覆盖用户的新编辑。

### 3.3 首轮视觉方案

主要人物和核心场景通过来自实际剧情的一组电影画面草案呈现，让关键人物进入相应环境，便于一起判断外观、服装、空间、光线和整体气质。

画面数量和选择由 Agent 按剧本决定。角色三视图、道具细节等制作资产按需准备，用户可查看；需要单独确认的细节再讨论。此处定义审核呈现，不规定所有图像资产的生成顺序。

### 3.4 代表性试拍

剧本与关键视觉方向确认后，共创默认先试拍一个实际剧情片段，呈现动态画面和关键声音。用户可以跳过审核或授权托管。试拍的长度、内容和镜头形式依剧本决定；合适的试拍素材用于成片。

用户不满意且语言沟通仍难明确方向时，可提议将同一小段剧情拍成两个差异明确的版本，经用户确认后生成对比。按需使用，避免把额外候选变成每次修改的必经步骤。

### 3.5 生成、剪辑与声音

以共享参考资产维护人物和世界，再按镜头需要选择文生视频、首尾帧或参考引导等路径，不要求所有镜头都完成同一套图片资产。

Agent 组织生成、选择候选、检查连续性、剪辑、字幕、配乐、配音、环境音效和按需动效。用户看到实际产物及进展；最终影片需结合整片声画检查，不能仅凭静态图好看判断完成。

H3 生成成功但动作、审美或连续性效果不合适时，也可在局部使用 Seedance 2.0 备选，不为正常模型切换反复要求许可。

两个模型均难以表现关键动作时，Agent 提出拆镜、换角度、声音叙事等拍摄调整。改变关键剧情的决定遵循共创／托管授权，不能擅自删去故事要点。

### 3.6 首版交付与继续修改

交付可播放、可下载的完整影片。项目继续保留剧本、素材、版本和修改能力，支持比较与恢复版本；剧本和素材可下载。专门的外部剪辑软件工程或 OTIO 导出延后，不是本轮 MVP 交付条件。

## 4. annotation 反馈与修改

采用所有者描述的 annotation 交互：用户在视频时间点写意见，标注自动回到对话输入框；可以逐条提交，也可积累多条后统一提交，并附加整体要求。

标注关联创建时的视频版本、时间点和意见。添加标注不自动发送或生成；视频变化后旧标注仍应可追溯。模型结合上下文判断修改范围，不把每条意见强制限定为一个镜头。

共创修改遵循理解、意见、方案、确认、执行；托管按授权范围推进。批量意见作为整体上下文处理，具体排序、合并和影响判断由模型完成。

支持在同一项目内新增或删除场景、改变故事结构。运行中收到修改要求时，具体暂停、继续、复用或重做哪些工作由模型判断；程序提供消息传递、任务控制、版本校验和真实状态。固定的“相关停、无关继续”调度规则已撤回。

## 5. 声音体验与成片后配音修改

声音审核融入试拍与成片预览，不增加固定的独立声音审核。默认结合画面试听，挑声线、比较配乐或听清音效时，可在对话或侧栏单独播放对应素材。

声音反馈复用 annotation，也支持整体自然语言修改。单独更换配乐不改变已认可画面；其他声音的独立试听、替换范围与实际保留的音轨对应，不能将混合音轨假定为可任意分离。

MVP 支持成片后修改台词、语气和角色声线。Agent 判断是独立调整声音，还是需要连带处理口型、表演或时长变化。必要时允许局部补拍；先说明修改方案，再按现有共创／托管授权执行。声音合成、分轨和补拍效果仍待真实验证。

## 6. 质量判断与产品评测

| 场景 | 已确认边界 |
|---|---|
| 用户创作中的剧本判断 | 人来判断是否有趣；Agent 给专业意见，最多可安排一轮专项审查后交用户看 |
| 运行中的媒体检查 | 检查生成内容是否符合剧本、身份与状态是否连续、动作和声音是否存在问题，并支持局部修复 |
| 正式剧本产品评测 | 设计单独维度和人评方法，属于离线产品评测，不能变成运行时自动打分改稿循环 |
| 整片产品评测 | 分别看故事吸引力、视听表现、连续性、声音、修改有效性与总体偏好；具体用例与方法待设计 |
| 技术检查 | 文件、编码、时长、音轨、版本和执行状态；技术通过不能替代电影质量结论 |

“有趣”是重要的作品评价目标，熟悉的题材和叙事也可以成立。不同叙事形式不能被统一反转模板或固定结构评分排除。有意的留白、黑场、时间跳跃等应结合创作意图判断。

## 7. 时间、成本与运行反馈

约 30 分钟和参考费用都是目标预期，不以达到某个时间或金额自动阻塞用户。试拍、对比、返工和配音补拍会影响实际结果，应如实显示进展、用量和费用。

验证时应记录生成与返工消耗、端到端耗时以及用户审核等待；具体统计口径需在实测前定义。系统错误、服务不可用和结果不符合要求应如实呈现，不宣称已经完成。重试与取消的技术策略留待架构评审，不在产品层枚举所有决策。

## 8. 本轮范围与延后项

本轮重点是跑通从自然语言到完整影片，再到有效修改的 MVP。

- 保留对话与侧栏式创作体验，不做专门的视频工作台或多轨时间线编辑器。
- 首版以电脑浏览器为完整创作入口，主要面向笔记本和台式机；手机端完整创作适配延后。
- 已确认本地个人部署：Agent 与项目存储在用户电脑上运行，生成能力调用已选云端 API；用户自备模型 API Key，由设置页引导配置和检查连接。首版正式支持 Windows，macOS／Linux 后续适配；安装分发方式待确定，详见[前端专项](frontend-spec.md)。
- 外部剪辑工程导出延后，项目内修改与恢复保留。
- Agent 数量不固定为七个；四角色试验基线也不等于最终架构。
- 已接受以 ViMax 作为新项目代码起点的方向，其运行时和具体模块均可替换；吸收 AdCraft、OpenMontage 的相应设计与能力。旧项目必要时可以完全舍弃，不要求兼容复用。
- 资源、比赛提交和公开部署属于后续执行事项，本次文档归并不启动代码、付费生成或发布。

## 10. 已被替代的早期假设

| 早期假设 | 当前处理 |
|---|---|
| 60–90 秒、默认全自动 | 90–120 秒；默认共创，支持托管与部分托管 |
| 约 300 元硬上限、超目标费用停止 | 撤回硬上限；费用目标不阻塞用户 |
| 固定六／七 Agent、自研运行图、必须复用现有 TS 工程 | 均不作为已定架构；按产品能力和验证结果评审 |
| 剧本自动评分、多轮改稿门禁 | 正式剧本评测归产品评测；运行时以用户判断和创作意见为主 |
| 必须生成全部角色板、场景板和分镜图 | 共享参考资产，按剧本及每镜需要组织 |
| 默认外部可编辑时间线／工程包交付 | 本轮延后外部剪辑工程导出 |
| 收到修改后固定暂停相关、继续其他 | 模型判断具体调度，程序保证执行与版本 |
| 旧十天排期与固定镜头探针配置 | 历史估算；当前实现排期和实测矩阵尚未冻结 |

早期来源与论证保留在[产品历史稿](../archive/2026-09-04/product-early-draft.md)。近期交互调研依据见[决定记录的来源部分](creative-interaction.md)。所有外部材料均不能覆盖所有者最新决定。
