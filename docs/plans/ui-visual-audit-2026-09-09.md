# UI 视觉优化 · 走查与方案草案

日期：2026-09-09。依据：用户选定03「显影」后要求「先梳理一下该怎么优化」。状态：**讨论草案，尚未实施本方案，也未取得本方案的人评**。品牌接入与既有验证见[视觉任务](./ui-visual-polish.md)。

## 1. 方向

让 Movie Agent 成为安静、清晰、有自身标识的电影创作工作区。阅读和表达容易开始；导演的真实工作可感知；生成的作品得到足够展示空间。

沿用03「显影」、A日间／B夜间、可收起项目导航、自然语言对话、对话专属资产库和单内容可见的多标签作品侧栏。共创与托管继续使用同一套界面。现有创作、保存、提交、审核和采用语义以[前端规格](../product/frontend-spec.md)为准。

本轮重点是信息层级与空间分配。Logo用于建立识别，作品本身承担丰富的视觉内容。界面采用克制的底色、清楚的排版和少量状态色；品牌图形集中在入口和导演身份处，避免在每个控件中重复装饰。

## 2. 走查依据与边界

- 代码基线：`0d643d1`，`feat/movie-runtime`。核对 [工作区样式](../../web/workspace.css)、[主页面](../../web/app.js)、[资产与作品页](../../web/panels.js)、[设置](../../web/settings.js)及现有前端规格。
- 本轮只读查看了已打开的欢迎页，实际视口约1699×901 CSS像素。该页未刷新，仍显示旧M标志，且保留未发送输入；未刷新或改动这份输入。因此它仅支持既有空间和排版问题的观察，不能作为03当前接入的验收。
- 该页欢迎标题起点约x719，输入框外沿约x595；灵感示例与输入区之间有明显空档。当前源码仍将欢迎内容与底部输入区分开组织。
- 当前样式中：对话正文和剧本编辑器14px；项目名称13px、项目状态10px；作品标签11px、版本标签10px；运行状态11px、输入区说明10px。重要状态与辅助说明的权重相近。
- 新走查标签被浏览器阻止打开，随即关闭；未尝试绕行。资产库、作品页和运行区的判断依据为当前代码与用户此前提供的截图，本轮未补做这些页面的新版本浏览器验收。03的既有日夜实看记录仍单独保留。
- 本轮没有发送导演消息、生成媒体、改变模式或采用版本，也没有启动、重启服务。

## 3. 问题与建议

| 优先级 | 区域与现状 | 建议调整 | 用户应感受到的变化 |
|---|---|---|---|
| P0 | 正文14px，大量状态与操作10–12px；淡色文字、细边框和按钮的权重接近 | 建立正文、操作、辅助信息三个清晰层级；重点提高模式、审核、未提交改稿和当前版本的可读性 | 不用逐个寻找小字，就能判断当前状态与下一步 |
| P0 | 欢迎内容与底部输入框独立排布，起始轴线不同，空白集中在两者之间 | 欢迎页将Logo、简短引导、输入框与灵感示例组成一个连续区域；示例放在输入框附近，按既有规格点击只填入 | 进入页面后视线自然落到「我想拍什么」 |
| P0 | 对话、Trace、最近产物、审核与任务入口同时出现，视觉主次偏弱 | 正文保持自然Markdown；真实运行摘要靠近输入区，历史细节可展开；最近产物维持少量入口；待审核事项突出内容与动作 | 阅读导演意见时，也能知道它正在做什么、是否需要回应 |
| P1 | 项目导航、页头与作品页有多个相近入口；收起导航时存在重复展开入口 | 统一选中、悬停和键盘焦点；区分项目级入口与作品级操作；精简重复按钮和侧栏展开入口 | 找项目、开资产和切标签的路径稳定且清楚 |
| P1 | 资产库有分类和搜索，但图片只有76×53缩略图，视频使用通用播放符号，声音与文稿呈现相近 | 「全部」保留混合列表；图片／视频分类提供更大的媒体缩略图排列，文稿与声音保留紧凑列表；优先呈现名称、类别、版本状态，技术信息作为次级内容 | 能直接辨认人物、场景与镜头，减少逐项打开成本 |
| P1 | 作品页在媒体前显示类型、时间、长标题、来源及解释；按钮多为相同样式 | 标题适度压缩显示，完整标题仍可查看；当前版本与状态清楚显示；将来源、ID和详细参数放入可展开详情；观看与标注操作靠近播放器 | 打开作品先看清内容，随后找到标注、下载或版本操作 |
| P1 | 剧本草稿中「保存」与「提交」并列，保存状态为11px | 「提交修改」作为明确动作，保存状态就近呈现；草稿与只读版本用固定位置和文字区分，冲突提示突出且保留内容 | 清楚自己是在编辑、已保存，还是已经交给导演处理 |
| P2 | 日夜主题已有基础，但媒体边界、状态和通用控件还缺少统一层级 | 分别调整背景层次、分隔线和状态色；沿用中文可读的系统字体；补齐焦点、加载、失败与停止反馈；少量短过渡尊重减少动态偏好 | 日间清爽、夜间舒适，状态变化明确且不打扰阅读 |

“最近产物”和资产库继续承接不同任务：前者提示本轮结果，后者保存整段对话的完整资产。视觉整理不得删掉历史产物，或将最近几项冒充完整资产库。

## 4. 建议的视觉起点

以下是第一版页面对照的试调值，尚未冻结为最终规格：

| 元素 | 建议起点 |
|---|---|
| 对话正文、剧本阅读与编辑 | 16px，中文行高约1.75–1.9；兼顾阅读长度和侧栏宽度 |
| 项目名称、操作按钮、作品标签 | 13–14px；增强当前选中项，长标题可截断但保留查看全文方式 |
| 时间、尺寸、快捷键等辅助信息 | 12px；必要状态使用更清楚的文字颜色，不只依赖小圆点 |
| 作品标题 | 20–24px；避免多层标题与说明共同占去预览空间 |
| 欢迎页标题 | 32–36px；缩小标题与输入框之间的距离，统一内容轴线 |
| 按钮 | 主要动作、次要动作、文字操作三类；常规按钮高度约32–36px；图标视觉尺寸与可点击区域分别考虑 |
| 空间 | 以4／8px节奏统一内部间距；按内容层级决定留白；三栏时优先保证正文与预览可读，保留用户调整侧栏宽度的结果 |

默认继续使用现有 Windows 系统字体组合。字号调整应与宽度、行距和按钮高度一起核对，尤其检查1366px三栏下的换行。夜间主题单独检查正文、次级文字、播放器周边与状态标签。

## 5. 运行状态与操作层级

常驻摘要回答「当前做什么、是否在等我」；展开后回答「谁执行了什么、有哪些结果或失败」。运行记录是可追溯的工具与任务事件，不呈现隐藏思维链。

- 导演回复、专业工作、云端媒体任务使用实际事件与状态标签；同一动作的准备、提交、查询、完成保持可区分。
- 需要审核时，让具体作品、版本与确认后的动作靠近呈现；审核请求的生成规则继续沿用既有授权。
- 发送与中止位置稳定；正在停止、已停止、云端仍在执行分别表述。异常用简短文字说明影响和可用动作。
- 流式更新保留阅读位置；用户上翻后才显示返回最新入口。切标签、刷新数据不抢输入焦点或重置播放位置。
- 动画只辅助真实状态变化；无进度来源时显示状态文字，不新增推算百分比或倒计时。

## 6. 纯视觉调整与小型能力补充

| 范围 | 内容与边界 |
|---|---|
| 现有前端可完成 | 字体、间距、颜色、按钮层级、欢迎页重排、已存在状态和来源的分层呈现、重复入口整理、图片显示布局 |
| 需少量本地媒体能力 | 视频封面从已有视频抽帧，按资产身份缓存；失败时保留诚实的占位与打开入口，不调用生成API。现有列表只有视频图标，不能把静态样张中的封面当作已实现 |
| 只展示已有依据 | 时长与分辨率来自已有媒体元数据；没有的字段留空或省略。音轨身份与可独立修改能力依真实素材记录，不凭图标推断 |
| 后续可考虑 | 音频真实波形、更多排序、复杂版本对比等单独评估；第一批视觉调整不依赖这些功能 |

底层在现有JavaScript与CSS中完成。整理 `styles.css` 与 `workspace.css` 的组件归属、重复覆盖及公共样式变量，避免继续叠加相互冲突的规则；本任务不需要迁移前端框架。

## 7. 推进顺序与验收

1. **第一批：可读性、欢迎页、对话区。** 一起核对日间／夜间，使用真实已有内容与隔离示例状态，比较开始创作、阅读、输入、运行摘要和审核入口。先取得这一批页面的人评，再向其他页面推广。
2. **第二批：资产库、作品页和剧本草稿。** 使用现有图片、视频、声音与历史版本检查素材辨认、预览面积、长标题和操作层级；视频封面本地抽帧独立登记。
3. **第三批：设置与边缘状态统一。** 沿用通用API填写方式，统一表单、按钮与错误提示；检查三栏宽度、导航开合、键盘焦点、减少动态偏好，以及断线、中止和保存冲突等状态。

验收分别登记视觉意见与功能结果。至少覆盖欢迎页、长对话／流式状态、待审核、资产库、草稿未提交、影片与批量标注、历史版本及异常提示；在1366和1600桌面宽度下查看主要布局。不能用静态截图宣称流式状态、播放保留或冲突处理已经通过。

界面验收不需要新生成电影素材。使用现有资产和明确标记的隔离测试状态；不得向用户当前项目自动发送消息来制造演示状态。故事趣味、连续性和托管判断力的缺口继续留在前期制作与能力任务中。
