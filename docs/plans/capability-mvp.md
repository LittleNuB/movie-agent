# 下一轮 · 真实电影能力建设

Status: next_iteration_requested_not_started

Date: 2026-09-06

## 决定与前置

用户在通用 API 设置调整后明确表示：“UI 可以暂定通过”，要求下一轮重点建设 Agent 的真实能力。现有三栏、作品标签、日夜主题及配置入口作为暂定交互基线；后续界面调整服务于真实能力接入、使用障碍修复和明确反馈，不继续以视觉打磨为主要交付。

本次记录暂定通过与下一轮衔接，没有开展真实模型调用或媒体生成。暂定 UI 通过不等于电影能力、运行可靠性或作品质量通过。

## 交付目标

争取跑通从零素材自然语言输入、多轮意图确认、剧本审核，到真实声画生成、90–120 秒影片和反馈修改的完整 MVP。约 30 分钟与费用预期仍是目标，不设硬停止条件。

| 能力 | 本轮应交付的实际行为与证据 |
|---|---|
| 导演与创作上下文 | 真实 LLM 理解不同想法、追问及修改，形成对应提案与剧本；使用工具，按共创或托管授权推进 |
| 视觉与镜头 | 按剧情维护共享人物、场景和必要道具参考，逐镜选择生成路径；产出真实图片和视频，记录来源、版本及失败 |
| 声音与成片 | 按剧本需要完成配音、配乐、关键声音、剪辑、字幕及必要效果；交付可播放的成片文件和实际音轨关系 |
| 修改与连续性 | 保存与提交分开；理解改稿或标注、提出方案并按授权执行；保留修改前后版本，说明素材复用和补拍，保护用户手改 |
| 执行可靠性 | 长媒体任务期间能沟通，真实记录中止、失败与恢复；持久化进度，处理结果不明和迟到结果，防止重复提交或覆盖新版本 |

## 实施顺序与边界

1. 以 AgentScope 为首选、ViMax 为电影领域代码起点，先核对具体模块、版本、许可和缺口，再复用或替换。AdCraft 与 OpenMontage 按已有研究边界吸收。不重新固定 Agent 数量。
2. 沿同一条真实链路分段交付：先真实导演与剧本，再代表性声画片段，随后扩展到完整影片和一次实际修改。每段展示真实产物及剩余问题。
3. 将通用连接、模型 ID 和用途接到实际 Provider。产品不预设模型；GLM、H3、Seedream、Seedance 是所有者个人使用与验证选择。既有接入授权按原用途沿用，不因进入下一轮重复确认方向；模拟连接检查不算真实接入。
4. 在实现中确定音频 Provider、凭据保存、消息交付及任务恢复方案，并记录选择依据。运行 API、数据库 Schema、最终角色数量不在此提前冻结；不引入旧 Pi 强制保留要求。
5. 原型仅提供交互参考。预设回复、Canvas 示例、计时演示和浏览器配置状态均不能作为正式能力实现证据。

## 验收与交付口径

- 目标交付至少一部真实生成并合成的 90–120 秒影片，以及同项目一次实际修改的前后版本；通过产品界面输入、审核和提交反馈，不能只在脚本中拼片。
- 记录实际输入、采用剧本、参考资产、调用与失败、重试、素材复用、耗时及可核对的费用。区分系统执行时间和用户审核等待，未知费用保留未知。
- 按既定[首轮验证矩阵](../validation/first-round-matrix.md)分批覆盖多个角色、场景、叙事任务和异常；逐项标明执行情况与证据。一部影片通过不能代表七组二十一个场景族全部完成。
- 故事趣味、电影质感、连续性与声音效果由人实际阅读和观看判断。正式剧本评测保持离线，不增加运行时自动评分循环。
- 依据真实产物和验证结论报告已完成、失败与未完成项。Mock、API 成功或界面状态变化不能替代真实电影能力和整片人评；不预先承诺达到参考电影的制作水准。
