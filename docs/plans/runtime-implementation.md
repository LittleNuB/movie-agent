## 实施基线

- 独立实现分支 `feat/movie-runtime`，起点 `6f15bed21a6ca52d3f0097fb45ae5f3136c518ba`；原型分支、旧工作区保持原状。
- Python 3.12、AgentScope 2.0.7.post1、FastAPI、SQLite、FFmpeg；uv 锁依赖，PowerShell 启动，无安装包。
- 主导演、按需视觉／后期／媒体检查；数量是验证起点。ViMax 固定版本方法移植，替换整片长流程和模型调用。
- 服务端 REST／SSE 与产物身份，用户草稿、不可变版本、明确提交与审核、任务恢复。凭据使用 Windows 凭据管理器。
- 产品模型配置初始为空；个人验证使用此前指定的 GLM、H3、Seedream、Seedance，新增 MiniMax speech-2.8-hd 和 music-3.0。图片、视频和音频适配分别验证。
- 声音保留独立配乐／配音及原生混合关系；按用户最新要求，H3 生成 768P、Seedance 2.0 Fast 生成 720P，FFmpeg 导出 720P、16:9、24 fps、48 kHz MP4，保留源文件、画面母版和字幕。此项替代初始 1080p 输出及短暂的所有视频生成 720P 要求，既有高分辨率结果不重生成。
- H3 默认中止只停止后续调度，本地任务按实际取消；不调用兼具删除语义的 DELETE，保留外部结果为候选。

## 执行与验证边界

按真实导演、代表性试拍、完整影片、实际修改与恢复、集成交付顺序推进。验证采用用户批准计划中的公开接口边界：项目与版本 API、模型／媒体 Provider、实际浏览器和成片。受控故障只验证控制路径，不能替代真实 LLM、真实媒体或人评。

沿用[七组二十一个场景族](../validation/first-round-matrix.md)，六类开发输入和两个保留输入，共创／托管各一部 90–120 秒影片及各一次修改。关键语义三种表述，C1／F1／F3 比较同模型同工具的单 Agent 与四类职责。记录每项证据、失败、未执行、复用、耗时、审核等待和可核对费用；不设费用硬停止。

完成后按 implement skill 做 Standards 与 Spec 审查，对照上面固定起点及用户完整计划。本轮源代码、真实调用、整片质量和人评分别给出完成状态。
