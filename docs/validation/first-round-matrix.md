# 首轮验证矩阵 · 范围已确认

**更新日期：** 2026-09-06

**状态：** 所有者已接受 AgentScope 2.0 为首选框架，并于 2026-09-06 确认本矩阵的七组、二十一个场景族作为首轮验证范围。真实运行验证正在执行，逐项状态见[本仓库执行证据](runtime-evidence-2026-09-06.md)；本文件定义范围，不代表全部通过。

**依据：** [产品基线](../product/product-spec.md)、[交互决定](../product/creative-interaction.md)、[架构形态与首选框架](../architecture/architecture-review-2026-09-05.md)。

## 1. 验证目的与数量口径

前一版三个场景主要覆盖插话、委派和恢复，只能作为可靠性冒烟检查，不足以判断首轮架构能否支撑电影产品。

本轮建议七组、二十一个场景族，覆盖创作、协作、视觉、声音、修改、可靠性与完整交付。一个场景族可以有正常与边界变体，不等于一次模型调用，也不等于生成二十一部电影。

两类结论分开：

- 架构与 Agent 是否能理解、委派、使用工具、回应修改，并维护正确的授权和版本。
- 真实 AIGC 路径能否得到值得观看、连续且可修改的影片。

完整影片必须纳入首轮验证目标，但轻量场景先行，不以完成全部正式前端和所有产品能力为开始验证的前提。

## 2. 证据类型

| 标记 | 必须使用的证据 | 能证明什么 |
|---|---|---|
| L | 真实 LLM、真实上下文与实际工具调用记录 | 意图理解、创作、委派、修改方案及授权判断 |
| M | 真实图片／视频／声音 Provider 产物与实际合成结果 | 生成质量、参考一致性、音轨和声画修改效果 |
| F | 可控事件、故障注入或有来源的回放 | 特定控制路径、异常恢复、重复或迟到结果的处理 |
| H | 用户或其他人工读者／观众的阅读、观看与反馈 | 故事吸引力、视听感受和修改满意度 |

F 不能替代 L 或 M。模拟媒体任务只能证明任务控制行为；回放真实缺陷素材可检查问题识别，但不能算作本次在线模型失败或重新生成成功。涉及界面体验的结论必须在实际界面复核，不能用直接提交结构化标注代替 annotation 界面验收。

## 3. 二十一个场景族

### A. 意图理解与剧本

| ID | 场景与输入 | 观察依据 | 证据 |
|---|---|---|---|
| A1 | 仅给一句模糊愿望，例如想要有宇宙尺度、但结尾温暖的科幻短片，不给素材 | 必要的多轮理解；可补充创意并区分用户要求与模型建议；形成含结尾及视听方向的提案 | L、H |
| A2 | 给出详细创作约束，包含多人、跨场景或非线性叙事要求 | 保留关键约束，不重复询问已知信息，不强塞单主角、固定反转或固定镜头模板；人评故事是否成立 | L、H |
| A3 | 用户手改正式剧本，先只保存，随后明确要求应用；期间存在基于旧稿的工作 | 保存不触发媒体变化；应用后基于新稿提出方案；旧结果不能覆盖手改稿 | L、F；正式侧栏补界面验证 |

### B. 共创、托管与授权

| ID | 场景与输入 | 观察依据 | 证据 |
|---|---|---|---|
| B1 | 共创模式走提案、剧本、视觉和试拍，包含一次不认可后修改 | 实际审核对应具体产物；用户确认后执行；进展与产物可见；不把阶段口头介绍当作已审核 | L、F，媒体阶段补 M、H |
| B2 | 明确全权托管完成作品 | 在授权范围内自主推进，避免重复要求已经授权的选择；仍能看到真实进展；不擅自改变明确创作要求 | L；完整路径补 M、H |
| B3 | 视觉共创、声音托管，随后切换到共创或调整授权 | 模型理解范围变化；已有素材和批准保留；后续动作遵循新授权，具体调度不预写为唯一答案 | L、F |

### C. 主导演与专业子 Agent

| ID | 场景与输入 | 观察依据 | 证据 |
|---|---|---|---|
| C1 | 对照一个简单修改和一个涉及视觉、剪辑与声音的复杂修改 | 简单任务可直接处理；复杂任务能合理分工、提供相关上下文并整合结果。不能以调用更多 Agent 作为成功标准 | L |
| C2 | 制作期间先提出讨论性问题，再提出明确修改 | 新消息能进入决策；区分讨论与执行要求；模型根据实际上下文选择暂停、继续或其他处理，并解释影响 | L、F；至少一轮真实媒体运行中复核 |
| C3 | 子 Agent 返回偏离委派要求、相互矛盾或失败的结果 | 主导演能识别并处理冲突或缺口，不将其直接当作完整成片；检查与生成职责能产生可用反馈 | L、F，可回放真实产物 |

### D. 视觉制作与连续性

| ID | 场景与输入 | 观察依据 | 证据 |
|---|---|---|---|
| D1 | 为实际剧情生成首轮视觉方案 | 用户看到关键人物进入对应场景的画面，能判断人物、空间、光线和整体气质；不是只检查文件生成成功 | L、M、H |
| D2 | 多角色在多个镜头或场景中出现，包含道具状态变化及有意的时间跳跃 | 身份与合理状态连续；关键变化按剧情发生；合法换景、时间跳跃不被机械判错；保留失败证据 | L、M、H |
| D3 | 按镜头选择文本／图像／参考输入，并处理当前主用模型成功返回但内容不合适的情况 | 路径选择有依据；必要时调用已配置并授权的备选并比较结果；无法表现关键动作时提出拍摄调整，遵循授权。所有者个人验证组合为 H3／Seedance 2.0，不是产品默认 | L、M、H；质量缺陷触发可用注明来源的回放 |

### E. 声音与声画修改

| ID | 场景与输入 | 观察依据 | 证据 |
|---|---|---|---|
| E1 | 观看带对白或其他关键声音、音乐和音效的试拍，按需单独试听 | 声画配合可判断；声音素材与实际音轨对应；无独立音轨时不假装能够单独播放 | L、M、H |
| E2 | 保留已认可画面，独立更换或调整配乐 | 所采用画面及其剪辑位置保留，音乐实际变化；检查对白、音效是否被意外损伤。仅比较 MP4 文件哈希不足以判断画面是否变化 | L、M、H |
| E3 | 修改一句台词、语气或角色声线，包含一个有清晰口型的片段 | 方案说明声音与画面的影响；能独立调整时保留画面，必要时局部补拍；对白、口型、时长和人物连续性共同检查 | L、M、H |

### F. 用户修改体验

| ID | 场景与输入 | 观察依据 | 证据 |
|---|---|---|---|
| F1 | 单条与多条 annotation；多条指向不同时间点，附加整体意见，并包含意见冲突变体 | 标注先进入输入框；提交后整体理解，无漏项；保留原视频版本；冲突得到明确处理，修改范围由模型判断 | L、F、实际界面；修改效果补 M、H |
| F2 | 用户说不清为什么不满意，语言讨论后仍需要观看对比 | 按需提出同一片段的两个有明确差异版本，经确认后生成；用户选择后正确沿用方向；不把对比变成每次修改必经步骤 | L、M、H |
| F3 | 分别测试新增／删除场景、改变故事结构，以及调整镜头顺序或长度，涉及字幕、对白和动作音效 | 明确应用并按授权执行后，新增内容实际生成并出现在新版，删除内容不再进入新版；后续剧情及字幕、对白、音效随修改更新；时间编辑保持动作与声音对应，旧版仍可追溯 | L、M、H |

### G. 可靠性与完整交付

| ID | 场景与输入 | 观察依据 | 证据 |
|---|---|---|---|
| G1 | 提交响应丢失、网络异常、重复消息或重复结果事件 | 请求结果不明时能查证而非盲目重复生成；记录实际请求和回执；故障注入结果与在线表现分开 | F；外部任务语义补真实接口验证 |
| G2 | 明确停止、进程中断后恢复、新版本出现后旧结果迟到，以及恢复旧成片版本 | 停止意图有效处理；取消请求与实际取消结果区分；重启后找回正确任务；迟到结果和旧标注不覆盖或错绑新版本 | L、F、M；版本恢复补实际界面 |
| G3 | 从自然语言到 90–120 秒完整影片，再完成一次用户反馈修改 | 全片可播放下载，故事与声画完整；修改前后可比较并可恢复；人工判断吸引力、连续性、声音和改动有效性 | L、M、H、实际交互入口 |

## 4. 分三批执行

### 第一批：真实 LLM 与可控任务环境

重点运行 A、B、C，以及 F1、G1、G2 中的语义和控制部分。LLM 必须真实调用；媒体结果可暂用有来源的既有产物或可控任务，明确只验证哪些行为。

无需先做完整正式界面；可通过测试入口输入剧本修改和标注对象。该方式不计作右侧手改、标注回流或播放器的界面验证通过。

### 第二批：真实媒体片段

运行 D、E、F2、F3，并补第一批涉及真实媒体的分支。使用真实图片、视频、声音和实际合成输出，形成可复用的项目与失败样本。

若没有自然遇到“成功返回但质量失败”，可以使用注明来源的真实缺陷候选触发重拍流程，并真实调用备选生成；不把注入或回放的缺陷计入在线失败率。

### 第三批：完整影片与修改闭环

建议至少完成两次完整制作，一次共创、一次托管，并至少各完成一次修改。影片满足 90–120 秒与默认输出要求。此前生成的合适素材可以复用，报告需明确复用量、新生成量和耗时起点，不能把缓存运行冒充全新制作速度。

两次完整影片只是首轮集成证据，不能据此推断所有剧本或复杂场景都稳定通过。

## 5. 输入覆盖与重复

建议准备六种开发输入：模糊创意、完整约束、多角色跨场景、非线性叙事、少对白的情绪表达、对白影响人物行动的故事。允许一个输入覆盖多个维度；这些是测试分布，不是产品创作模板。

另准备未用于改提示或调流程的保留输入，用于最终完整制作和必要的泛化检查。保留输入的数量与具体内容在实际执行前确定并记录；不得调完后仍声称它是未见样本。

对意图理解、授权、委派和批量标注等易受模型波动影响的关键场景，建议使用不同表述重复 2–3 次。实际次数在报告中逐项列出，不将一次成功写成稳定成功率。

## 6. 判断方法

- 剧本与整片吸引力由人阅读或观看后判断，说明具体理由；首轮可由所有者主审，条件允许时加入独立读者或观众。不能让被测 Agent 自己打分后宣布有趣。
- 故事关注吸引力、信息可理解性、人物动机与事件关系、结尾效果及用户意图。不同叙事形式采用适合其意图的判断，不强制反转或单一结构。
- 媒体同时检查单个产物、跨镜关系与整片声画；分辨率、文件可解码或静态画面漂亮不替代观看判断。
- 授权、手改保护、标注版本、重复提交等检查有可观察的正确结果；发现越权执行或版本覆盖应明确记录为缺陷。
- 不给创作策略设唯一标准答案。委派方式、暂停范围、镜头路径或补拍方式只要满足意图、授权和产物约束，可以有多种有效结果。
- 每项记录通过、失败、未执行或证据不足，并注明证据类型。技术通过、模型行为通过和人工质量判断分列，不合成一个掩盖问题的总分。

## 7. 失败归因与架构比较

| 归因层 | 例子 | 对选型的意义 |
|---|---|---|
| 基础 LLM 与提示／上下文 | 误解创作要求、未理解多条意见 | 优先检查模型和上下文，不能直接认定框架不适合 |
| Agent 职责与协作 | 委派丢信息、各自修改冲突、主导演未整合 | 检查角色边界与交接是否需要拆分或合并 |
| 运行框架与应用接入 | 新消息进不来、后台完成未唤醒、恢复重复执行 | 检查具体框架机制及接入；证实关键缺口后再评审 LangGraph 等备选 |
| 电影领域与版本管理 | 标注指错版本、旧结果覆盖、改稿被回写 | 修改应用的产物、授权和版本实现 |
| 媒体 Provider 与后期 | 人物漂移、动作失真、口型不符、混音错位 | 检查生成路径、参考和后期能力，不把所有问题归给 AgentScope |

对 C1、F1、F3 等有区分度的任务，建议用同一 LLM、输入、素材与工具集合比较单 Agent 和四类职责基线，记录质量、耗时、调用量与费用。只有出现具体分工瓶颈，再增加拆分方案；不要求把二十一个场景对所有候选架构穷举一遍。

## 8. 执行前准备与报告

执行前确定测试入口、LLM 和各媒体 Provider 的实际模型版本、凭证接入、输入与初始产物、运行批次和费用记录方式。2026-09-06 的[基础接入检查](provider-preflight-2026-09-06.md)是早期真实 GLM 工具调用及媒体只读查询；随后真实图片、视频、声音和 LLM 用例已在本仓库执行，详见[运行证据](runtime-evidence-2026-09-06.md)。两份记录的范围不能混用。

每次运行至少保存：场景 ID、输入和反馈、所用版本、委派与工具记录、前后产物、异常是否注入、人工意见、失败归因、系统耗时、审核等待、生成与复用量、实际费用。

约 30 分钟和目标费用用于观察差距，不是产品硬停止条件；测试支出与生产目标分别记录。首轮用例覆盖已获认可，下一步形成具体执行任务与调用安排；本矩阵不代表已完成产品验收。
