# 科幻电影导演 Agent 产品方案报告

**项目：** digital-human-agent-mvp 方向调整与 AI+∞ 电影 Agent 赛道方案
**日期：** 2026-09-04
**状态：** 讨论稿，不替代当前 `DESIGN.md`，不代表已授权实施、模型调用、部署或参赛提交

> **后续讨论提示 · 2026-09-05：** 本文为早期研究稿，尚未完整同步后续决定。60–90 秒、默认全自动、角色数量及外部可编辑时间线交付等表述不能作为当前已确认规格。当前目标时长为 90–120 秒，默认共创并支持授权托管；首次故事提案结构已另行确认，见[已确认记录](../../product/creative-interaction.md)。该记录仅覆盖其声明的范围，其余讨论仍需整理。

## 所有者校正 · 2026-09-04

- **已接受：** 本轮目标成片时长为 60–90 秒。
- **已否决：** 将单主角、单空间、单异常作为产品或首发能力边界。该组合仅作为一个低复杂度测试用例。
- **产品方向：** 科幻电影 Agent，不能固化为只生产一种剧本结构的 Agent。
- **仍待讨论：** 角色与场景复杂度、叙事方式、对白/表演、镜头数量、画幅、自动化与人工控制、架构及模型选型。接受时长不代表接受其余研究建议。

## 1. 结论摘要

建议把参赛产品定义为一个有明确边界的「科幻电影导演 Agent」：用户输入一句关于未来的设想，系统在默认全自动模式下完成故事设计、视觉圣经、镜头计划、素材生成、粗剪、整片审查、定向修复、声音设计和交付，最终产生一部 60–90 秒、有完整声画、过程可追溯、结果可继续编辑的原创科幻短片。

当前讨论对象是科幻电影 Agent，应能根据不同故事组织人物、世界规则、场景、叙事和视听方法。长期后期导演方向仍是项目背景；本轮不据此替所有者决定比赛后的产品定位。竞赛提供了验收场景，但不构成将产品压成一种剧本的理由。原先基于低复杂度范围的十天可行性估计需重新评估。

现有工程值得保留。持久项目、版本、撤销、恢复、成本记录、Remotion/FFmpeg、素材权利、审查包和项目包都直接有用。需要重做的是产品领域层和创作合同：旧的「上传主视频—推荐模板—确认模板—生成首版」不适用于从一句话生成电影，也不应继续成为新方向的核心。

## 2. 为什么现在要调整

### 2.1 比赛要求已经改变了验收问题

电影 Agent 赛道的评分由五部分组成：

| 评分维度 | 分值 | 产品必须证明什么 |
|---|---:|---|
| 多 Agent Harness 架构与工程实现 | 30 | 角色分工、调度、状态、上下文、反馈、重试、可观测、本地/云协同与合规 |
| 统一一句话生成测试 | 25 | 评委给一句话后，系统能理解、规划并稳定生成完整成片 |
| 技术创新与模型工程 | 25 | Agent 协作、自评修正、模型部署/路由、资源调度有真实实现 |
| 自主作品质量 | 10 | 至少一部叙事、画面、声音、剪辑和风格完整的作品 |
| 复现、开源与部署 | 10 | 代码、文档、复现成本和魔搭创空间部署可信 |

报名截止为 2026 年 9 月 14 日 12:00，作品提交截止为当日 22:00。Agent 需要部署到魔搭创空间，并提交记录工作流、模型和工具的创作手记；作品需为 1–5 分钟原创科幻视频，带 AI 生成标识并满足素材、版权、IP 和肖像权要求。来源：[AI+∞ 开发者创作大赛官网](https://modelscope.cn/active/AIstudio)。

当前项目在工程可靠性上有优势，在「一句话从无到有造电影」和自主作品质量上仍是空白。继续做旧 Ticket 20–23 无法补上这个缺口。

### 2.2 最新研究与项目根因相互印证

项目此前对口播成片的根因审查指出：固定模板轮换、单帧审查、缺少信息节拍、对白精修、声音设计、调色和整片观看，使 Agent 变成模板微调检查员。

外部研究得到相同结论。FilMaster 将当下 AI 电影的关键缺口归为镜头语言和电影节奏，采用场景级镜头语言规划、粗剪、观众反馈、精剪、多层声音和可编辑时间线；FilmBench 发现当前模型静态画面往往尚可，动作表演、镜头运动、跨镜连续和多镜头剪辑明显更弱；DirectorBench 发现最低分往往发生在镜头单元之间。[FilMaster](https://arxiv.org/html/2506.18899) · [FilmBench](https://arxiv.org/html/2607.24241v2) · [DirectorBench](https://arxiv.org/abs/2605.30090)

因此新产品的质量单位应从「单个模板组件」改成「一个叙事节拍、一个镜头、相邻镜头关系和整片体验」。

## 3. 产品定位

### 3.1 一句话承诺

> 输入一句关于未来的设想，电影导演 Agent 在可追溯、可恢复、可定向修复的制作流程中，交付一部 60–90 秒、有完整声画、可继续编辑的原创科幻短片。

### 3.2 第一用户

第一用户是有故事构想和基本审美判断，但缺少完整剧组、模型工程能力和大量后期时间的独立创作者。竞赛评委是第一个外部验收者，但产品不应只为评分页面设计。

第一付费价值候选是「降低从想法到第一条可看的完整微电影的综合成本，同时保留对过程、质量与修改的控制」。速度只是其中一个维度；如果结果仍是分镜幻灯片或随机视频拼接，等待时间再短也没有价值。

### 3.3 产品边界

本轮已确认的范围参数只有 60–90 秒。产品不以单主角、单空间、单异常为前提，也不要求所有故事采用一种节拍顺序或视听风格。

多人互动、多场景衔接、不同科幻规则、并行或非线性叙事、对白与表演均需进入能力讨论；它们尚未被证明可实现，也尚未被所有者排除。人物、场景、镜头和故事结构的具体上限应在讨论与实测后确定。

原先的 8–10 镜、16:9、少旁白/少对白、限制正面对口型等建议均保留为待选制作策略，不能自动转为产品限制。预算和模型限制应以任务级诊断、拆解、模型选择和明确协商处理，不得静默删角色、合并场景或替换故事。

版权与授权边界独立于创作复杂度：不得擅用受保护素材、人物肖像或声音；公开发帖、部署、付费和提交仍需授权。公共执行环境的安全方案也仍需独立验证。

比赛页面的「一个人 + 一个空间 + 一件小事」属于选题建议，不能推导为 Agent 的产品限制。本报告最初将其提升为首发边界的推断已撤回。[比赛官网](https://modelscope.cn/active/AIstudio)

## 4. 核心体验

### 4.1 默认路径

1. **一句话开拍**
   用户输入设想，例如「城市最后一台会做梦的售货机，在停电前把一个梦交给了夜班保安」。可选时长，其他设置均有默认值。

2. **导演拆解**
   系统根据创意形成故事蓝图，组织人物及关系、科幻世界规则、事件、场景、叙事顺序和表达目标；不强制每个故事都具备同一种异常、选择或反转。界面用简短自然语言展示，不要求用户填写制作表格。

3. **建立视觉世界**
   生成角色、空间、关键道具、光色和声音母题的视觉圣经。所有镜头都引用同一批稳定身份，不让每个提示词重新发明角色和世界。

4. **镜头计划与开拍**
   系统按叙事、表演、空间关系和节奏确定镜头数量与长度；8–10 镜仅为可选测试配置。候选数量和并行范围按每镜风险、模型能力与预算安排。

5. **连戏与局部补拍**
   连戏监督检查人物、服装、道具、空间、光色、动作起止和相邻镜头。失败只回退到相关镜头、提示编译或锚点，不重跑整部片。

6. **粗剪到精剪**
   第一条完整粗剪出现后，整片审查叙事、节奏、转场和声音。剪辑声音导演调整镜头顺序、时长、声桥、旁白、环境、音乐和动作声，形成画面锁定与最终混音。

7. **交付与复现**
   用户获得 MP4、字幕、制作台账、模型与素材回执、修复记录、项目包，并在能力可用时获得 OTIO 可编辑时间线。

### 4.2 用户界面

默认界面保持四个区域：

- 一句话输入与后续对话；
- 主播放器；
- 制作进度图，显示故事、视觉、生成、连戏、剪辑、声音、审片；
- 镜头列表，显示状态、候选和局部重做。

高级详情再展示 Agent 输入输出、提示版本、模型、Token、费用、重试、质量回执和许可证。不要把 Agent 之间的自然语言讨论当作主要视觉表演；展示应聚焦可核验的产物和修复前后差异。

### 4.3 自动与人工的关系

统一一句话测试要求默认无人工确认完成。真实产品仍允许用户：

- 暂停与继续；
- 修改故事方向；
- 锁定人物或镜头；
- 选择候选；
- 对一个时间段提出意见；
- 撤销或建立备选版本。

人工介入是增强控制的能力，不应成为系统完成基础成片的隐形必需条件。

## 5. 科幻导演知识与方法候选

### 5.1 科幻的内容原则

BFI 将科幻概括为以大观念表达我们对未来的希望和恐惧，视觉奇观只是外在特征。优秀低预算科幻常从普通生活、主观体验、声音和一个可信的异常切入。[BFI 科幻主题资料](https://www.bfi.org.uk/bfi-distribution/bfi-international-distribution/touring-programmes/sci-fi-days-fear-wonder) · [BFI 低成本科幻制作](https://www.bfi.org.uk/bfi-film-academy-opportunities-young-creatives/bfi-film-academy-how-do-i-work-film-television-industries/create-sci-fi-effects-budget)

这些资料提供可选创作方法，不足以定义全部科幻电影。建议讨论的通用能力包括：

1. 理解创作者希望表达的科幻命题和观众体验。
2. 维护世界规则及其后果，允许多个设定，但检查冲突与信息负担。
3. 根据故事组织人物关系、场景与事件，不强制日常空间或单一主角。
4. 在悬疑、冒险、人物关系、动作、诗性或其他表达中选择适合的叙事方法，具体覆盖待确认。
5. 让镜头、表演、声音与剪辑服务表达目标，避免把某种结尾或反转作为通用验收条件。

### 5.2 低复杂度测试用例的方法示例

下面六个节拍只适用于一个「单主角、单空间、单异常」测试用例，不是默认剧本生成模板。其他用例可以使用完全不同的叙事结构。

| 节拍 | 观众任务 | 推荐画面责任 |
|---|---|---|
| 日常基线 | 理解人物、空间和规则 | 稳定建立镜头、可辨识环境声 |
| 异常出现 | 发现一个不应存在的变化 | 道具/局部特写、声音先行 |
| 验证失败 | 排除偶然，建立疑问 | 主观镜头、反应、遮挡或负空间 |
| 选择或拒绝 | 人物承担行动与代价 | 表演保持、克制推近或静止 |
| 后果显现 | 世界规则被改变 | 空间尺度、光色或声音结构变化 |
| 余波画面 | 留下可回想的主题 | 回到首镜构图或声学母题，改变一个细节 |

该方法可用于观察基础链路和局部修复。仅通过这个用例不能证明产品的科幻电影创作通用性，也不能据此要求其他故事遵守相同节拍。

### 5.3 镜头生成约束

MAViS 的生成兼容研究建议：每个镜头只承担一个简单动作，避免细小文字和连续复杂动作；人物、手、背影、环境和关键道具特写可作为过渡并减少相邻镜头的背景漂移。[MAViS](https://aclanthology.org/2026.eacl-long.101/)

这些经验应记录为特定模型和工作流下的风险提示，不是通用电影语法。候选处理方式包括：

- 先保留完整动作与交互意图，再按模型能力决定一次生成、分段生成或补拍；
- 区分成片镜头与模型生成片段，不能用单次调用限制替代影片设计；
- 屏幕文字可选择后期可控图形重建；
- 按剧情时空和人物/道具状态检查连续性，允许有意的换景和时间跳跃；
- 运镜、插入镜头和声音衔接应有表达理由，不能为了避错机械插入；
- 对白、旁白和动作长度按实际镜头节奏同步，而非固定少对白。

### 5.4 视觉语言

「导演语法卡」可作为知识表示候选。以下七类属于低复杂度用例的示例集合，不能视为完整知识库：

- 空间建立；
- 孤独与尺度；
- 异常道具特写；
- 主观怀疑；
- 选择时的表演保持；
- 后果揭示；
- 首尾构图回声。

多人调度、视线关系、跨场景衔接、并行剪辑和复杂行动等知识尚需结合首轮能力目标继续讨论，不能因示例集合未包含就被排除。

每张卡包含叙事责任、建议景别、视角、构图、允许的动作复杂度、声音层和禁用条件。Sundance 的视觉叙事课程把信息、情绪、感官、视点与叙事视为镜头选择的任务，并强调构图、景别、空间关系和有动机的运镜。[Sundance 视觉叙事](https://collab.sundance.org/catalog/Visual-Storytelling-The-Shot-The-Camera-On-Demand)

### 5.5 声音语言

声音分三层设计：

- 场景层：环境与音乐，建立空间和情绪弧；
- 镜头层：旁白或对白，承担信息；
- 镜内层：动作声、提示声、拟音，绑定精确事件。

日常声音异化、远近空间、声学母题、声桥和留白是一组可选策略，不适合自动套在每种科幻电影上。声音方案应按对白、动作、情绪和场景目标选择。Sundance 的短片建议强调配乐服务叙事。[Sundance 短片建议](https://www.sundance.org/blogs/pep-talks-and-advice-for-makers-of-short-films-from-our-sundance-programmers/)

## 6. 多 Agent 产品分工

角色数量不是卖点。建议六个角色，每个都有独立产物和验收责任：

| 角色 | 产物 | 不允许做什么 |
|---|---|---|
| 故事导演 | 故事蓝图、节拍、主题、结尾 | 不直接调用视频模型 |
| 视觉导演 | 视觉圣经、场景状态、镜头计划 | 不私自改故事核心因果 |
| 生成制片 | 模型请求、参考包、并发与预算计划 | 不自由重写镜头意图 |
| 连戏监督 | 跨镜问题与局部修复指令 | 不直接提交最终版本 |
| 剪辑声音导演 | 粗剪、画面锁定、声音计划与混音 | 不用特效掩盖故事缺口 |
| 观众审片 | 整片检查点、时间范围和修复优先级 | 不用单一总分替代证据 |

中央调度器负责状态、分支、重试和停止，不作为会聊天的角色。外部研究表明，多 Agent 常因角色规范不清、Agent 间错位、验证和终止失败而失效，因此所有交接应为严格结构化产物。[MAST 多 Agent 失败研究](https://arxiv.org/abs/2503.13657)

## 7. 差异化

### 7.1 与研究型电影 Agent 的差异

FilmAgent、MovieAgent、MAViS 已覆盖剧组角色、分层规划与生成评价。我们不主张首次提出这些环节。可建立的差异是：

- 生成、修复、版本和审查使用同一持久状态；
- 每个镜头和声音决定都有来源、父版本和费用；
- 跨镜问题可以定位到最小修复范围；
- 失败可恢复，人工可以接管；
- 最终交付包含可编辑项目，不只是一条 MP4。

### 7.2 与现有开源产品的差异

OpenDirector 已有一句话、九角色和 Docker，但实际主媒体 Runner 以图像、配音和音乐为主，并使用内存检查点；Butterfly Director AI 的完整架构文档领先于当前真实编排。我们的竞争线应是「真实多镜头视频 + 持久恢复 + 跨镜修复 + 完整声音与可编辑交付」，避免比角色数量和页面复杂度。[OpenDirector](https://github.com/seme-org/open-director) · [Butterfly Director AI](https://github.com/abhijha8287/butterfly-director-ai)

### 7.3 与闭源生成平台的差异

单个视频模型可以生成漂亮短片段。电影导演 Agent 的价值在于把一句高层意图编译为跨镜头、跨模态、可恢复和可修改的工程，并对失败负责。模型随时可以替换，故事、世界、镜头、版本和评价合同继续存在。

## 8. 质量与评测

### 8.1 三层门禁

1. **技术门禁**：文件可解码、时长/画幅/编码正确、无黑帧/长静音/削波、字幕在安全区。
2. **镜头与跨镜门禁**：主体/背景一致、动作自然、提示遵循、人物/道具/空间状态连贯、转场和声音连续。
3. **整片门禁**：故事忠实、因果清楚、节奏有效、声画有层次、结尾成立、愿意直接观看或发布。

VBench 可覆盖主体、背景、闪烁、运动、动态与审美等通用指标；FilmOps 可识别景别、构图、角度、色调、人物布局和镜头运动。FilmBench 同时提醒，通用 MLLM 或单一审美分数不能代表电影级判断。[VBench](https://github.com/Vchitect/VBench) · [FilmOps](https://github.com/Neo-yk/FilmOps)

### 8.2 竞赛前基线

原先仅按四个主题凑八条提示的方案不足以检验通用性，需改为主题与制作复杂度交叉覆盖。以下是待讨论的测试维度，不是已经承诺支持的能力或新故事模板：

| 候选用例维度 | 主要验证能力 |
|---|---|
| 单主角、单空间、单异常 | 基础链路与受控回归，仅一个低复杂度用例 |
| 多人物及同场互动 | 身份区分、关系、调度、对白/动作衔接 |
| 多场景及人物再次出现 | 跨场景状态、位置和时间关系 |
| 不同科幻设定与叙事形式 | 世界规则、因果/叙事关系及方法选择 |

具体用例、数量、优先级和能力上限需继续确认。开发用例与保留用例必须分开。对可比较的测试条件固定时长和预算，比较：

- 新的六角色系统；
- 单 Agent 使用相同模型和工具；
- 去掉整片审片与局部修复的版本。

记录全流程完成率、首次可看片时间、镜头重生率、成本、故事忠实、角色/空间一致、动作自然、剪辑流畅、声音可懂、吸引力和总体偏好。自动分数用于定位；最终产品结论需要匿名整片人评。

### 8.3 参赛成功线

最低交付线：

- 一句话无需人工确认即可完成 60–90 秒视频；
- 所有 Agent 产物、模型调用和重试有可查看轨迹；
- 至少一次真实失败可恢复；
- 有一部完整原创科幻成片；
- 魔搭创空间可访问；
- 有公开代码、Mock 模式、安装文档和创作手记。

上述是交付候选线，不能仅凭一个低复杂度用例宣称完成科幻电影 Agent。首轮能力验收还须覆盖所有者选定的不同复杂度与叙事任务。竞争线候选包括跨镜问题更少、整片盲评更好及局部修改有效，均需实测。

## 9. 版本路线

### 9.1 竞赛版 v0.5

- 一句话到 60–90 秒科幻短片；
- 面向不同科幻创作任务的方法与能力框架，具体首轮覆盖继续讨论；
- 六角色有界编排；
- H3 主路径、Mock 模式、本地模型接口；
- 粗剪、连戏、声音、整片审片；
- Studio 部署、公开复现和一部自主作品。

### 9.2 比赛后的产品验证

先验证三个问题：用户是否愿意为完整首版而非单个片段付费；跨镜修复是否真的减少返工；电影导演包能否迁移到产品演示、品牌短片或知识叙事。

科幻创作通用性需要在本轮范围和测试中体现，不能延后到比赛后才讨论。比赛后是否扩展到其他视频类型或转向 Finishing，应由验证结果和所有者再次决定。

## 11. 产品风险

- **生成质量风险：** H3 尚未用本项目故事实测。若 9 月 7 日三镜头探针不能稳定通过，切换到可用 API 组合，不继续押注本地部署。
- **人物一致风险：** 先尝试参考、模型、局部修复或拍摄方法调整；减少人物或隐藏正脸等会改变创作意图的降级需用户同意。
- **结构固化风险：** 按用户希望的电影形式判断作品是否成立，不要求所有故事都有相同主角、异常、选择和反转。
- **Agent 表演风险：** 若角色没有独立产物、工具或判断责任，则合并，避免为了评分制造空角色。
- **成本风险：** 只对高风险镜头生成双候选；局部重生，禁止整片无界重跑。
- **版权风险：** 只用原创/授权素材，不把电影片段直接纳入镜头 RAG；使用抽象电影语言标签和自有范例。
- **公开仓库风险：** 不直接公开私有主仓的历史媒体、路径、凭证和未澄清素材。

## 12. 需要下一轮决定的问题

60–90 秒已获接受，不再与其他限制捆绑提问。单主角、单空间、单异常只用于一个低复杂度测试用例。

1. 首轮应覆盖哪些不同人物、场景、叙事与表演复杂度的制作任务？
2. 是否冻结旧 Ticket 20–23，并建立独立 v0.5 电影领域层？
3. H3 三镜头实测预算上限是多少？
4. 目前是否已有 ModelScope 账号、实名认证、创空间或 DGX Spark 申请状态？
5. 参赛开源采用新公开仓库，还是从私有主仓抽取镜像？

## 13. 证据边界

FilMaster、FilmBench、DirectorBench、Hollywood Town 等包含 2026 年新近论文或预印本，样本数和评审规模有限。它们支撑设计方向，不能证明本方案一定提高成片质量。模型能力、速度和显存主要来自供应商或作者资料，尚未在本项目环境复现。比赛未公开隐藏测试提示、调用预算和并发规则，应通过官方答疑渠道确认。
