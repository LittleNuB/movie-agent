# 把故事拍清楚：Movie Agent 生成质量研究

2026-09-09 · 面向产品所有者与后续开发 · 研究建议，尚未成为实施规格

## 1. 直接结论

应优先补齐电影前期设计与参考资产工程。用户提出的两个问题有明确依据：剧本缺少人物动机、事件因果和可见动作，会把未完成的创作任务转移给视频模型；参考资产缺少可靠的身份、空间和状态约束，会使不同镜头各自重新设计人物与场景。上一轮建议偏重生成后的检查，这轮研究支持把更多投入前移。

已经有可复用的方法和实现：**分层故事计划、人物状态记录、主形象派生参考、场景空间设计、镜头首尾状态、参考选择与版本绑定、带声音的分镜预演**。这些共同构成一套更完整的制作依据。不过，公开经验的成熟度不相同：传统制作方法比较成熟，闭源 API 的适用方式取决于版本，自动拍好完整电影仍没有可直接继承的成功保证。

**一个重要修正：资产库可以保存人物多视图，但不能把三视图作为所有视频调用的默认输入。** Seedance 2.0 系列当前官方指南明确不建议人物多视图输入，建议面部特写与全身形象分开；ViMax 的多视图用于后续选图，其选择器也按目标视角选用。两者在用途上可以协调。[Seedance 提示词指南](https://www.volcengine.com/docs/82379/2222480)、[ViMax 参考选择](https://github.com/HKUDS/ViMax/blob/05a48943878312d88fe5a016c12a9654940ecc43/agents/reference_image_selector.py)

本轮完成公开文献、官方接口及固定源码研究，并只读检查本地项目。未生成新图片、视频或声音，未修改产品运行代码、用户剧本、模型设置与采用关系。以下方法需要后续真实模型和人评验证。

## 2. 我们具体缺在哪里

检查基线为 Movie Agent `587d50b`。目前已具备文稿版本、真实参考参数、异步生成与媒体观察，缺口集中在创作依据是否完整，以及这些依据是否真的进入每次调用。

| 观察 | 已有证据 | 对质量的含义 |
|---|---|---|
| 剧本设计主要依靠提示词 | `STORY_CRAFT` 要求动机、因果与可拍摄动作；文稿结构化数据仍主要为自由字典 | 原则已经写了，但缺少能追踪缺失前提、状态变化与镜头兑现情况的稳定产物 |
| 参考能力存在，实际使用少 | 《回声频率》共6张图：2张来自图像生成任务，4张来自视频抽帧；14条视频任务里12条没有登记参考，另2条使用单首帧 | “生成过图片”不能证明图片约束了影片；需检查实际引用链 |
| 参考用途与质量缺乏完整承接 | 工具能校验资产存在、类型与版本；没有完整的人物主形象、服装状态、视角与场景覆盖管理 | 需要把可用文件进一步组织为制作资产 |
| 采用与内容检查未充分关联 | 托管可自动记录采用；当前视频观察只取三帧且不听音频 | 有真实文件仍不足以说明关键动作与声画成立 |

上述14条是任务记录，包含失败与重试，不是14个独立镜头，也不是成功率；本轮没有重新观看全部产物，不能据此断言所有画面均不一致。用户关于故事无聊、看不懂的意见仍为有效人评。[当前创作提示](https://github.com/LittleNuB/movie-agent/blob/587d50bc11add7bb87bb3c4782a1db23ed009fdc/src/movie_agent/prompts.py)、[制作与审核工具](https://github.com/LittleNuB/movie-agent/blob/587d50bc11add7bb87bb3c4782a1db23ed009fdc/src/movie_agent/film_tools.py)、[媒体观察](https://github.com/LittleNuB/movie-agent/blob/587d50bc11add7bb87bb3c4782a1db23ed009fdc/src/movie_agent/media.py)

## 3. 剧本：先完成故事设计，再转成拍摄依据

### 已有方法提供什么

Re³ 将写作计划、相关人物事实、早期摘要与近期原文共同用于续写，并用紧凑人物属性记录处理事实冲突。其研究对象是英语长故事，实验收益来自多种机制，不能归功于一句“保持逻辑一致”的提示，也不能直接换算为电影达标率。[Re³，EMNLP 2022](https://aclanthology.org/2022.emnlp-main.296/)

DOC 使用详细层级大纲约束事件、场景和人物。后续官方 v2 的 `OutlineNode` 明确保存节点身份、场景、参与人物、父子关系，并能构造相邻和上层上下文。可复用这种表示与上下文组织；原版包含 token logits 控制，无法直接通过 GLM 聊天 API 照搬，v2 也不等同于复现原论文全部实验效果。[DOC，ACL 2023](https://aclanthology.org/2023.acl-long.190/)、[官方 v2 数据结构](https://github.com/facebookresearch/doc-storygen-v2/blob/main/storygen/plan/outline.py)

Dramatron 从一句话故事逐层形成角色、场次、地点和对白，并允许人在各层修改。它适合借鉴剧本分层，官方明确没有将其设计或评测为自主托管系统；专业人士研究涉及15人，上演剧本经过大量人工改写。[Dramatron 官方说明](https://github.com/google-deepmind/dramatron)

叙事规划研究 IPOCL 还区分两种成立条件：世界中的前提允许一个行动发生，以及人物有理由选择这个行动。其符号规划实验场景受限，可借鉴分析问题的角度，无须给短片引入完整规划器。[Riedl 与 Young，Narrative Planning，JAIR 2010](https://arxiv.org/pdf/1401.3841)

### 对 Movie Agent 的建议

保留用户能直接阅读和手改的完整剧本；在背后维护一份精简的制作说明。模型可以自主设计内容，程序保存来源、引用和当前状态。以下是建议字段，不冻结数据库 Schema：

| 设计对象 | 至少回答的问题 | 常见缺口 |
|---|---|---|
| 世界规则 | 能做什么？条件与代价是什么？ | 结尾临时出现一种能解决问题的新能力 |
| 人物动机 | 他想要什么？知道什么之后改变选择？ | 只有“他感动了”，没有可理解的触发 |
| 关键事件 | 前提、行动、结果、后续影响分别是什么？ | 事件顺序相邻，但没有因果或有意关联 |
| 信息安排 | 人物知道什么？观众现在知道什么？何时揭示？ | 决策依据只存在于幕后设定里 |
| 状态变化 | 人物、物件、空间从什么状态变成什么状态？ | 道具易主、受损、移动没有过程 |
| 镜头兑现 | 哪个动作、画面或声音承载这一变化？ | 镜头都很有气氛，关键剧情没有被表现 |

一次专业逻辑审查可围绕上述问题，指出具体位置与缺失依据。它负责找矛盾和不可拍摄的表达，不给故事趣味打分，不自动无限改稿。保留有意留白、误解、不可靠叙述与开放结尾；“闭环”意味着关键选择与后果有设计，不能变成每件事都向观众解释一遍。

**示例，仅用于说明方法，未修改现有影片：**“工程师决定切断电源救人”仍缺必要信息。可以设计为：门被失控电机夹住；备用电池仅能维持紧急照明；他看到同伴手套被卡住，选择拉下总闸；电机停转但舱室变暗；同伴获救，导航因此失效。是否采用这段故事仍由创作判断，但前因、代价、行动与结果已有可拍内容。随后应明确拉闸动作、门的运动、电机停声和照明变化由哪些镜头表现，而非再加一串“震撼、史诗、电影感”。

## 4. 资产：建立可用的标准，再按镜头挑选

### 多视图应怎样做

ViMax 固定版本的 `CharacterPortraitsGenerator` 确实先生成正面全身图，再把该图作为真实图像参考生成侧面和背面，保存独立结果。这提供了可复用的派生流程，避免三次独立文生图各自重新设计人物。[人物多视图源码](https://github.com/HKUDS/ViMax/blob/05a48943878312d88fe5a016c12a9654940ecc43/agents/character_portraits_generator.py)

Runway 的官方实践提供另一种基础：用光线均匀、表情中性的主体图开始，分别迭代人物与环境，再组合为镜头画面；选定服装变化后，将那个具体版本保存为后续参考。它展示了单参考与多参考用法，但没有证明固定三视图或固定数量在所有模型上最优。[Runway 图像参考指南](https://help.runwayml.com/hc/en-us/articles/40042718905875-Creating-with-Gen-4-Image-References)

**建议资产包如下，生成数量随剧本变化。** 主角跨镜出现时，应有稳定身份来源；只有需要侧背细节、转身或相应机位时，才补充对应视角。三视拼版可以给人审阅，模型输入另行选择。

| 资产 | 要解决的具体问题 | 建议制作方式 |
|---|---|---|
| 人物面部主参考 | 跨镜辨认同一人 | 清晰面部、简单背景、适合辨识的光线；采用版本保持稳定 |
| 全身及服装参考 | 身材比例、服装、鞋与装备 | 引用主形象派生；服装与身份分别标记 |
| 侧面、背面、局部 | 侧脸、背包装备、头盔接缝等确有戏份的细节 | 从同一主形象派生，检查通过后作为补充视角 |
| 场景整体与关键机位 | 门窗、走道、操作台的相对位置 | 先做纯场景整体设计；正反打、转角与局部按实际拍摄补齐 |
| 关键道具及状态 | 道具大小、归属、完好／破损、开启／关闭 | 单独设计可辨识外观，变化版本关联发生的事件 |
| 镜头起始构图 | 同框关系、站位、视线、画面重点 | 组合人物、场景与道具；先解决空间表达，再生成运动 |
| 结束构图或动作参考 | 必须到达的结果、难描述的动作／运镜 | 仅在镜头确有需要且 Provider 支持时制作或选择 |

资产除了文件和名称，还应记录：对应人物／场景、用途、故事时间、外观状态、视角、父参考、采用版本、检查依据，以及后续哪些镜头使用了它。受伤、湿衣、道具转移属于合理变化，不应被“一致性”纠正回初始状态。

### 标准参考与新生成结果的关系

GroundShot 把人物、道具、场景分别管理，保护标准参考，仅将可靠的新视角纳入补充；还允许先制作更适合建立参考的镜头，最后恢复故事顺序。其54份剧本、309镜头的实验采用4秒、720p无声片段；同后端对照与消融支持实体参考和生产次序的作用。它是未独立复现的预印本，未在本轮找到可确认的公开代码入口，不证明 H3／Fast 上的收益。[GroundShot v3，2026-07-20](https://arxiv.org/html/2606.20799v3)

对应的产品建议是：开场远景或背影不适合做人脸标准时，可以先生成专门身份图；成功生成的文件先作为候选，只有身份、清晰度和状态合适的部分才能升级为参考。上一镜尾帧可以帮助相邻动作衔接，但长期身份不能只依赖不断变化的最近一帧。

场景也需要实际空间覆盖。一张漂亮的驾驶舱正面图不能定义驾驶舱反面；补充机位应继承门、窗、控制台等位置关系。复杂科幻空间后续可评估简易平面图、布局草图或3D预演，但本轮证据不足以要求所有影片都采用3D建模。

## 5. 把工程落实到当前模型

### 需要区分三种输入路径

| 路径 | 适用情形 | 具体交给模型什么 |
|---|---|---|
| 文生视频 | 无持续身份要求的环境、抽象或探索镜头 | 简洁的镜头事件、视觉方向和声音意图；仍检查实际输出 |
| 镜头图／首尾帧生视频 | 人物站位、道具位置、构图或起止状态需要精确表达 | 已完成构图的单帧，必要时加尾帧；文字集中描述动作、变化与声音 |
| 多模态参考生视频 | 多主体身份、场景、动作或声音需要分别参考 | 少量各有职责的图像／视频／音频，并明确每份素材控制什么 |

输入图像承担构图与外观、视频提示补充运动，是 Runway Gen-4 的官方用法；首尾帧制作也有火山的图像辅助视频实践。它们支持这类分工，具体提示词规则仍不能跨模型照抄。[Runway 视频指南](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)、[Seedream 4.0 辅助视频案例，历史版本](https://www.volcengine.com/docs/82379/1951250)

### 已核对的接口边界

**MiniMax H3。** V2 支持文生、首帧／尾帧／首尾帧与多模态参考；首尾帧角色不能与参考图、参考视频、参考音频混用，多模态参考图片上限9张。我们继续使用768P。若镜头需要人物与场景分别约束，可先合成正确的镜头图走首帧，也可走多模态参考，不能拼出接口不支持的组合。H3 Max 的参考限制不同，不混作 H3 能力。[H3 创建接口](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create)

**Seedance 2.0 Fast。** 当前 API 的2.0系列支持首尾帧及全模态参考，Fast支持720p；不同输入模式互斥。参考模式可以在文本中描述期望的首尾构图，但这不等价于严格首尾帧约束。[创建任务 API](https://www.volcengine.com/docs/82379/1520757)

官方提示词指南指出人物多视图可能被识别为多个主体，建议独立面部特写加全身图，并强调空间关系用图表达、参考素材避免堆满。因此，电影资产库可以留侧背视角；Fast 的默认调用应先采用其推荐组合，额外视角只在对应任务中验证。[Seedance 2.0 系列指南，2026-09-08更新](https://www.volcengine.com/docs/82379/2222480)

**Seedream 5.0 Pro。** 当前专属教程确认 `doubao-seedream-5-0-pro-260628` 支持单图／多图参考生图、局部交互编辑与图层拆分，但普通文生组图和图生组图暂不支持。多视图应逐张派生，或在有实测依据后另选支持组图的模型；一张底图加若干透明图层不能当作多个完整镜头。既有适配器能传参考图，尚未把专属编辑和资产工作流完整产品化。[Pro 专属教程，2026-09-08更新](https://www.volcengine.com/docs/82379/2582774)

**会影响真实引用链的条件。** 方舟对含人脸素材有专门输入机制：部分同账号、同平台、近30天内的原始模型产物受信，包括规定范围内的 Seedream 5.0 lite／pro 文生图。二次编辑、压缩转发可能使这一资格失效。工程上需要保留原始产物来源，不能默认“本地裁切的脸图”“H3 视频抽帧”能直接通过 Fast 的同一路径。受信范围之外应使用平台实际提供的适用机制；不得把换模型或改变文件包装用于绕过审核。[肖像素材官方说明](https://www.volcengine.com/docs/82379/2608626)

**可试验的新接口。** H3-Context-IR 接受多模态上下文并返回增强的视频提示词，不直接生成影片。可作为候选输入编译步骤，对比它是否补足空间、动作和声画细节；输出必须保留原意，不能自行增加角色、镜头或配乐后直接执行。本轮未接入或测试。官方列价按输入／输出 token 分别计费，不是免费步骤。[Context-IR 接口](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-h3-context-ir)、[官方计费](https://platform.minimaxi.com/docs/guides/pricing-paygo)

## 7. 建议的制作过程与最小实现

建议仍由主导演统筹、专业职责按需参与，沿用 AgentScope 和现有资产库。新增的是可执行的制作方法与产物，不先固定更多 Agent，也不增加用户必须填写的专业表单。

1. **故事设计。** 形成完整故事与关键事件依据，做一次有位置、有理由的逻辑审查；按现有共创／托管授权决定采用。
2. **制作拆解。** 从采用剧本得到人物、地点、道具、状态变化，以及实际拍摄需要的素材清单。
3. **建立视觉标准。** 生成并检查主角、服装、场景、关键道具；按镜头需求补视角。固定的是采用版本，后续创作变化仍可以形成新版本。
4. **分镜预演。** 用粗分镜、临时对白与声音安排整片时长，检查信息顺序和动作时间。可在现有右侧作品页播放，无须新增视频工作台。
5. **按依赖试拍。** 选择真实难点：人物同框、道具交互、复杂空间或关键动作。先验证后续会依赖的视觉标准，再安排其余生成。
6. **镜头输入编译。** 根据当前状态、目标构图、所需参考和实际 Provider 形成输入。每份参考均有明确作用，保留调用时采用的版本。
7. **结果检查与局部修改。** 对实际声画检查可观察问题，保留合格素材，定位缺失动作和状态错误，选择重做图片、补拍或后期调整；最终故事感受由人判断。

分镜预演有传统动画制作依据。Pixar 与 Khan Academy 课程将分镜、构图、运动、反馈与 storyreel 作为创作内容；它适合把“看不懂”的问题提前暴露。预演只证明计划表达和节奏可读，不证明视频模型会完成同样的运动。[Pixar × Khan Academy 课程](https://www.khanacademy.org/computing/pixar/storytelling)

连续性拆解也有现成职业方法：场记在拍摄前按故事日、人物、服装、道具和动作拆解，拍摄中记录实际连续性。可借鉴职责，但不能因此声称视觉模型已经胜任全部场记判断。[ScreenSkills 场记职责](https://www.screenskills.com/job-profiles/roles/script-supervisor-film-and-tv-drama/)

**建议优先实现三个模块：**剧本制作说明、参考资产与依赖管理、镜头输入编译。先把它们接到现有发布文稿、图像生成、视频生成和版本工具；再补分镜预演与重点检查。领域方法可以按需以 Skill 形式加载，但 Skill 文本、资产文件、执行记录三者都要有，不能只新增几份提示词。

在资产库中建议显示“对应人物／场景”“当前用途”“派生来源”“哪些镜头使用了它”，让用户可以审阅。生成中间资产由 Agent 完成；是否展开查看由用户选择。共创保留既有关键审核，托管不为每一张图重新索取授权。

## 8. 怎样判断改进确实有效

本报告建议先分别测剧本设计与参考工程，避免更换故事、模型和参考方法后无法解释收益。以下均为待执行设计，未消耗之前的媒体额度。

| 对照 | 保持什么不变 | 看什么结果 |
|---|---|---|
| 当前写法 vs 分层事件＋制作说明 | 同一创意、推理模型与创作要求 | 缺失前提、无动机转变、状态冲突；盲读者能否复述关键因果 |
| 文生 vs 统一主参考 | 同一镜头内容、视频模型、规格与时长 | 身份、道具和场景是否更稳定；先形成基础参考收益证据 |
| 主参考 vs 按视角／状态选图 | 同一剧本、模型和目标镜头 | 同场景反打、转身、道具易主、衣着变化能否同时成立 |
| 首帧路线 vs 多模态参考路线 | 同一目标镜头与视觉标准 | 构图控制、关键动作、多人关系、生成耗时与可用素材量 |
| 原始提示 vs H3-Context-IR | 同一素材、镜头意图、生成配置 | 增强提示是否忠实；是否增加未经需要的镜头、配乐或情节；最终质量有无收益 |

对照不要求每个题材都走所有组合。先用少量重复样本验证机制，找到有效方法后再扩大；跨模型分别报告，不混成一个成功率。延续已确认的六类开发输入与两个保留输入：身份跨镜、同场景正反打、多人关系、道具状态变化、跨场景回访、关键情绪与动作表达都应覆盖，最后回到90–120秒完整影片。

人评分两次：先读剧本，判断动机、逻辑与吸引力；再让未读剧本的人看影片，复述发生了什么。剧本能读懂而成片不能，优先追查镜头兑现与剪辑信息；剧本本身就不成立，先回到故事设计。用户的趣味判断继续保留，不由自动检查替代。

记录采用前后的资产、新生成与复用量、返工原因、首次可用镜头比例、最终影片接受情况、产品外介入次数、时间和费用。所有失败与重试进入成本分母。参考设计新增成本应与减少的视频返工一起核算，不能仅比较单次视频单价；约30分钟与费用仍是目标，不新增硬停止阈值。
